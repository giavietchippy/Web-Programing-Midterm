## Step 1 additions (websocket-contract.md)
1. Renegotiation rule: after the first connection, a peer that adds or removes a track (e.g. screen share) sends a NEW `offer` over the same RTCPeerConnection, and the other side answers. Use the "perfect negotiation" pattern: the polite peer is the one with the lexicographically smaller peerId. On an offer collision, the polite peer rolls back and accepts the incoming offer; the impolite peer ignores it. Add a short table and a second Mermaid diagram: "Peer A starts screen sharing -> renegotiation".
2. New message `media-state` (client): `kind` ("camera" | "screen"), `active` (boolean), `streamId` (string). The server adds `from` and broadcasts it to the other peers without inspecting it. `peer-left` implies that peer's media-state is inactive.
3. Add JSON examples for both and add `media-state` to the message table.
